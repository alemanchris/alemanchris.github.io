import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from scipy import stats

plt.rcParams['figure.figsize'] = (7, 8)

rng = np.random.default_rng(1234)   # Set seed for reproducibility

# This loop simulates the random variable
x_vec = np.empty((N, 3))

        axes[i].hist(x_vec[:, i], bins=num_bins, density=True, color='steelblue', edgecolor='white')
        axes[i].set_ylabel('pdf')
        axes[i].set_title(f'Bins $=\,${num_bins} $\mu=\,${mu[i]} $\sigma^{{2}}=\,${sigma[i]**2}')
    plt.tight_layout()
    plt.show()

Activity 2: Kernel Density (Estimation)

Histogram:

$$f^{hist}(x)= \frac{1}{N}\sum^{N}_{i=1}\frac{1}{b} \textbf{1}_{x_{i}\in[x-0.5b,x+0.5b]}$$

Where $b$ is the bin width.

Kernel:

$$f^{Kernel}(x)= \frac{1}{N\hat{b}}\sum^{N}_{i=1}K\left(\frac{x_{i}-x}{b}\right)$$

Where $\hat{b}$ is the bandwidth and $K(\cdot)$ is the kernel function. The most common types are:

  1. Normal
  2. Box
  3. Triangle
  4. Epanechnikov

Practical Example

scipy.stats.gaussian_kde plays the role of MATLAB's ksdensity. It only ships a Gaussian kernel, but it lets us hand it any bandwidth we like via bw_method, which is all we need here (MATLAB's own bandwidth choices are ad-hoc constants, not kernel-specific either).

# Pick one simulation:
N2 = 300
x2 = rng.normal(loc=mu[1], scale=sigma[1], size=N2)   # Simulate again

support_grid = np.linspace(-4, 4, 100)

# Default-bandwidth kernel density (Scott's rule, scipy's default)
kde_default = stats.gaussian_kde(x2)
density_default = kde_default(support_grid)
default_bw = kde_default.factor * x2.std(ddof=1)      # effective bandwidth used

# Theoretical (true) density
true_density = stats.norm.pdf(support_grid, loc=mu[1], scale=sigma[1])

fig, ax = plt.subplots(figsize=(7, 4.5))
ax.hist(x2, bins=50, density=True, color='lightgray', edgecolor='white', label='_nolegend_')
ax.plot(support_grid, density_default, 'r-o', markersize=3, linewidth=1.2, label='Kernel Density')
ax.plot(support_grid, true_density, 'b-x', markersize=3, linewidth=1.2, label='Underlying Density')
ax.set_ylabel('pdf')
ax.legend()
plt.tight_layout()
plt.show()

# Now compare a few explicit bandwidths
bws = [default_bw, 1.8, 3]
fig, ax = plt.subplots(figsize=(7, 4.5))
ax.hist(x2, bins=50, density=True, color='lightgray', edgecolor='white', label='_nolegend_')
styles = ['r-', 'r--', 'r-.']
for bw, style in zip(bws, styles):
    kde = stats.gaussian_kde(x2, bw_method=bw / x2.std(ddof=1))
    ax.plot(support_grid, kde(support_grid), style, linewidth=1.2, label=f'Kernel BW = {bw:.4g}')
ax.set_ylabel('pdf')
ax.legend()
plt.tight_layout()
plt.show()

Simulate Data from any distribution

The inverse CDF method

$$x = F^{-1}(u)$$

Where $F$ is the CDF of the desired distribution and $u$ are draws from $U(0,1)$.

Repeat the above example for the Generalized Pareto distribution. scipy.stats.genpareto uses the same shape convention as MATLAB's gprnd/gppdf (positive shape k gives an unbounded, heavy tail), so we implement the inverse-CDF simulator ourselves (as in the original) and check it against scipy's own density.

def sim_gp(n, k, sigma, theta, rng):
    """Simulate from a Generalized Pareto via the inverse-CDF method.

    Inputs
    ------
    n     : number of draws
    k     : shape parameter (xi)
    sigma : scale
    theta : threshold / location
    """
    u = rng.random(n)
    return sigma / k * ((1 - u) ** (-k) - 1) + theta

N3 = 5000
sigma_gp, k_gp, theta_gp = 1.0, 5.0, 0.0

x3 = sim_gp(N3, k_gp, sigma_gp, theta_gp, rng)
x3 = x3[x3 <= 10]           # trim the extreme tail, as in the original
N3 = x3.size

Activity 3: Spurious relations

$$x_{1} = \beta_{0}+\beta_{1}x_{2}+\epsilon_{1} \qquad x_{3} = \alpha_{0}+\alpha_{1}x_{2}+\epsilon_{3}$$

Two variables that are each driven by a common third variable $x_2$ will show up as correlated with each other, even with no direct causal link between them.

Note on reproducibility. Numbers here will not match the MATLAB output digit-for-digit — numpy's default_rng and MATLAB's Mersenne-Twister rng don't produce the same stream even from the same seed. What matches is everything that actually matters pedagogically: the shape of the densities, the bandwidth trade-offs, and — in Activity 3 — three correlations all sitting comfortably above 0.9, illustrating the same spurious-relation story as the original.
